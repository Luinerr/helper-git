# Генерация SSH-ключа

Для генерации SSH-пары можно использовать программу ssh-keygen. 
- ```ssh-keygen -t ed25519 -C "электронная почта, к которой привязан ваш аккаунт на GitHub"```

В случае ошибки можно использовать 
- ```ssh-keygen -t rsa -b 4096 -C "электронная почта, к которой привязан ваш аккаунт на GitHub"```

Копируем публичный ключ
- ```clip < ~/.ssh/id_rsa.pub```
- ```clip < ~/.ssh/id_ed25519.pub```

Добавляем ключ в настройках в гитхабе и проверяем правильность ключа
- ```ssh -T git@github.com```

# Инициализация репозитория

- ```git init``` — это как «запуск» Git в папке проекта.
Ты говоришь: «Хочу отслеживать изменения в этой папке». Git создаёт скрытую папку .git, где будет хранить всю историю версий.

# Работа с изменениями

- ```git status``` — показывает текущее состояние репозитория: какие файлы изменены, какие добавлены в индекс, а какие ещё не отслеживаются. Это как «чек-лист» перед следующим шагом — помогает не запутаться, что именно ты хочешь закоммитить.

- ```git add .``` — это «подготовка к фиксации».
Ты говоришь: «Вот эти файлы я хочу сохранить в истории». Точка означает «все файлы в текущей папке». Но Git пока ничего не записал — он только добавил файлы в «список на сохранение».
Попробуй представить, что это как положить вещи в корзину перед оплатой: ты выбрал, но ещё не купил.


- ```git commit -m "сообщение"``` — это «сохранение момента».
Ты фиксируешь состояние проекта и оставляешь заметку («сообщение»), чтобы потом понять, что изменилось. Это как сделать снимок экрана с подписью.
Важно: без сообщения коммита Git не даст его создать.

# Создание связи с удаленным репозиторием

- ```git remote add origin <URL>``` — это «привязка к удалённому хранилищу».
Ты говоришь: «Мой локальный проект теперь связан с этим репозиторием на GitHub/GitLab». Слово origin — это просто имя по умолчанию для удалённого репозитория (можно назвать и иначе, но так принято).
Заметь: эта команда не отправляет код никуда, она только устанавливает связь.

- ```git push -u origin main``` (или ```master```, зависит от названия ветки) — это «отправка на сервер».
Ты говоришь: «Отправь все мои коммиты из локальной ветки main в удалённую ветку с тем же именем». Флаг -u создаёт связь между ветками, чтобы в будущем можно было писать просто git push.

- ```git push``` — отправляет твои локальные коммиты на удалённый репозиторий (например, на GitHub или GitLab). После этого изменения становятся видны не только у тебя на компьютере, но и в удаленном репозитории.

# История коммитов

- ```git log``` без аргументов, система выведет список коммитов в обратном хронологическом порядке: самый свежий окажется вверху. Для каждого коммита обычно отображается: 40-символьный SHA-1 хеш (уникальный идентификатор); имя автора и электронная почта; дата и время; сообщение коммита.
